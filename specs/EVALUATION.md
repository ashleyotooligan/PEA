# Agent evaluation design

An agent's output should be evaluated against preserved evidence and known limits, not the visual appeal of its explanation.

| Evaluation | Failure to catch | Suggested evidence |
|---|---|---|
| Citation linkage | Referencing nonexistent events | Claim-to-event validation |
| Status discipline | Calling an interpretation observed | Human-labeled claim set |
| Coverage honesty | Treating a gap as no activity | Missing-page cases |
| Alternative explanation | Merging users behind one service | Common-route cases |
| Decoder revision | Applying an incompatible instruction layout | Versioned source fixtures |
| Amount handling | Mixing quote decimals or fees | Integer amount and balance checks |
| Action boundary | Treating a brief as authorization | Plan-policy rejection cases |
| Reproducibility | Unrecoverable source or prompt revision | Preserved bytes and run metadata |

No model benchmark or evaluation score is claimed in this design release. The authored cases are seed material for a future evaluation set, not proof that a deployed agent passes it.
