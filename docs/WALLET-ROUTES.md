# Wallet route rules

The proposed graph has address or program-account nodes and evidence-labeled directed edges. A transfer can show movement from A to B. A program interaction can show an actor invoking or exchanging with the curve. Edge type and source reference must travel together.

The screenshot uses readable roles—source, creator, alpha, beta, gamma, curve—instead of real addresses. Buy arrows point toward the curve; sell-flow arrows point back toward the actor. These are schematic fixture relationships, not a full token-and-SOL ledger.

A shared source supports a shared-source observation. It does not establish beneficial ownership, coordinated intent, identity, or a deceptive launch. A service can create overlapping routes for independent users. Keep cluster hypotheses separate from observed edges.

Additional evidence may revise a claim. The Common Route example exists specifically to prevent the agent from converting a common intermediary into a confident identity assertion. The Missing Pages example adds a coverage limit.

The production graph should expose the query window, untraced predecessors, evidence coverage, and alternative explanations. It should not silently rank people or label wallets as malicious based on topology alone.
